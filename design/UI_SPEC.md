## 0. 设计判断

**在读什么**：给一款 16:9、纯 DOM/CSS、零图片的浏览器 Roguelike 生存游戏重新做一整套界面。观众是玩家自己，主要在战斗页长时间盯屏。

**语言选择**：东方水墨 × 克制的信息设计。不是"仙侠手游"那套烫金描边+发光按钮，是**墨底 + 少量丹青色 + 强字阶对比**。

**设计三档**

| 档 | 值 | 理由 |
|---|---|---|
| 设计张力 | 6/10 | HUD 必须有纪律，用非对称（左窄右宽、边角承重）制造张力，但不允许花活 |
| 动效强度 | 5/10 | 只做反馈型动效（受击闪、按下、面板入场），不做装饰型循环动画 |
| 信息密度 | 7/10 | 战斗页接近「驾驶舱」：数字多、必须一眼分层 |

**三条例外声明**（明知故犯，写下来免得以后被当错误改掉）
1. **衬线体**：只用于中文标题与牌面。默认不用衬线是网页铁律，但本作的题材就是"印在宣纸上的江湖"，宋体/楷体的笔画气质是内容的一部分，不是装饰。
2. **象牙色大面积出现**：只允许出现在麻将牌面与结算主数字上，绝不用作界面底色。
3. **回字纹角标**：东方形制的几何装饰，只用 4 个角、每角 2 段线，不铺边、不做繁复纹样。

## 1. 铁律（违反即回退 PR）

1. **每个颜色只有一个职责。** 见 §2。看到一个新颜色，先问它替谁干活。
2. **战场中央 60% 永远不放 UI。** 打开战斗页标尺自检（导航栏有开关）。
3. **会变的数字必须等宽 + `tabular-nums`。** 数字跳动一次，界面就脏一次。
4. **全局只有一盏灯，方向恒定左上。** 任何组件不许自己打光。见 §4.5
5. **明度必须落带。** 背景永远不许比敌人亮。见 §4.6
6. **间距只用 8 档、圆角只有 3 个、动效只有 3 档时长。** 不许临时值。
7. **一屏最多一个实心金色按钮。** 主行动唯一。
8. **禁止裸 `z-index`。** 只能用 `--z-*` 令牌。
9. **零图片、零外部字体、零构建。** 质感靠渐变 / `box-shadow` / `mask` / 伪元素。

## 2. 色板：语义契约

这是整套设计的核心。**颜色不是氛围，是信号。**

| 令牌 | 色值 | 唯一职责 | 绝对不许用在哪 |
|---|---|---|---|
| `--zhu` 朱砂 | `#c8402f` | **威胁**：敌血、自身受伤、突变状态、危险等级、禁用态 | 玩家的按钮、可选项、货币 |
| `--qing` 竹青 | `#2f8f6b` | **状态与恢复**：增益、治疗、冰冻/永冻共鸣、经验条、经验石 | 威胁提示、货币 |
| `--jin` 鎏金 | `#b8912f` | **价值与可交互**：三种货币、价格、主 CTA、选中态、暴击数字 | 危险提示 |
| `--ivory` 象牙 | `#f2ece0` | **牌面与最关键文字**：麻将牌、结算主数字、强调白 | 任何大面积底色 |
| `--ink-*` 墨阶 | `#0b0f12`→`#7b8d97` | **结构**：表面、描边、文字层级。无语义 | — |

**为什么这样切**：红绿是玩家最敏感的两个信号色。把红锁给"威胁"、绿锁给"增益"之后，玩家扫一眼战场就知道局势；金是全场唯一的"我的钱/我的选择"，所以主按钮和价格天然最显眼 —— 不需要额外加发光。

### 墨阶（9 级，只用 6 级）

| 令牌 | 值 | 用途 | 对 ink-800 对比度 |
|---|---|---|---|
| `--ink-900` | `#0b0f12` | 页面底 / 进度条槽 | — |
| `--ink-800` | `#131a1f` | 基础表面（行、卡片底） | 基准 |
| `--ink-700` | `#1a232a` | 抬升面板、hover 行 | — |
| `--ink-600` | `#27333c` | 控件底、hover 控件 | — |
| `--ink-500` | `#33424c` | 强描边、面板边框 | — |
| `--ink-400` | `#465761` | 常规描边、回字纹角标 | — |
| `--ink-300` | `#7b8d97` | 三级文字、角标标签、禁用态 | **5.1:1** ✓ AA |
| `--ink-200` | `#9fb1bb` | 次要正文 | **7.9:1** ✓ AA |
| `--ink-100` | `#c3d1d8` | 正文 | 11.2:1 ✓ AAA |
| `--ink-050` | `#e4ecef` | 标题、最高优先文字 | 14.6:1 ✓ AAA |

强调色对 `--ink-800`：朱砂亮 4.7:1、竹青亮 6.8:1、鎏金亮 9.8:1 —— 全部通过 AA。

**明令禁止**：纯黑 `#000`、纯白 `#fff`、任何彩色玻璃拟态、任何外发光描边、暖米色/黄铜色作为界面底色（那是"精品电商"默认审美，跟麻将江湖无关）。

## 4. 形制：为什么是"两笔描边"

这套界面看起来"有体积"而不"在发光"，全靠一个配方：

```css
box-shadow: var(--edge-soft), var(--edge-lit);
/*          ↑ 1px 冷描边定轮廓   ↑ 顶部 1px 内高光定厚度 */
```

- **面板** `--ink-700` 系底 + 1px `--ink-500` 描边 + 顶部内高光
- **回字纹角标**：4 角 × 2 段短线 = 8 条 `linear-gradient`，纯 `background-image` 实现，零元素。默认 `--ink-500`，只在两种容器上换色：**鎏金**（值得注意）、**朱砂**（有威胁）
- **顶栏强调线** `.rail`：2px 横线，是唯一的"区块头"信号，颜色跟语义走
- **表面**：`--surf`（墨底 84%~90% 渐变）+ `backdrop-filter: blur(10px) saturate(.85)`

### 圆角（3 个，用完了）

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--r-0` | 0 | 面板、按钮、输入、进度条、徽章 —— **默认全直角** |
| `--r-tile` | 3px | 麻将牌（真牌就是圆的）、英雄铭牌 |
| `--r-pop` | 2px | 浮动弹层（三选一、结算、tooltip） |

### 4.5 光：全局只有一盏灯

> 这一节是 v1.1 补的。第一版最大的问题就是**只做了压暗、没做打光** —— 一片均匀的黑不是"有氛围"，是"没做完"。

**全局一盏主光，方向恒定为左上偏上**（`--sun-x: 22%` / `--sun-y: 4%`）。所有轮廓光、所有落影、所有明暗过渡都必须服从这个方向。**不允许任何组件自己打光。**

| 层 | 实现 | 作用 |
|---|---|---|
| 主光锥 | `radial-gradient` 于 `--sun-x/--sun-y`，`--light-core` → `--light-mid` → 透明 | 决定画面哪边亮 |
| 体积光束 | 两道 102° 的 `linear-gradient` 光带，`--shaft` `.05` | 给暗场一点"空气里有东西" |
| **玩家光池** | 跟随玩家的 `radial-gradient`，620×500，`--light-player` | 玩家是场景里唯一移动的光源，跑到哪亮到哪 |
| 敌人自发光 | 每个敌人一圈 `box-shadow` 外发光 | 只发光不照地，避��� N 个光源的性能坑 |
| 纵深衰减 | 屏幕上方 30% 一层 `linear-gradient` 压暗 | 俯视角没有"地平线"，用压暗代替远山 |
| 底部雾 | `linear-gradient` 到 `--fog`，40% 高 | 前景与中景分离 |
| 尘埃 | 8 个 3px 圆点，22s 一轮向左上飘 | 唯一"在动"的空气感 |

**轮廓光（rim light）是可读性的地基。** 割草类游戏里 200 只怪要能一眼扫完，靠的不是细节，是剪影。纯 CSS 下的做法：

```css
.foe::before {                       /* 受光面，方向必须跟主光一致 */
  content: ""; position: absolute; inset: 0;
  background: linear-gradient(148deg, rgba(255,248,234,.52) 0%, rgba(255,246,230,.10) 36%, transparent 58%);
}
```

敌人 = **暗色本体（明度 22%）+ 左上受光面（42%）+ 1px 亮边描边 + 面纹汉字 + 落影**。面纹（`兵/铁/影/弓/巫/盾/爆/裂`）不是装饰 —— 它让敌人读起来是"牌灵"而不是"调试色块"。

**血条只在受伤时出现。** 满屏 20 条红杠是纯噪声，还会掩盖真正被打残的那几只。

### 4.6 明度带（value chart）

背景永远不许比敌人亮。这是"满屏怪也能读"的前提。

| 带 | 目标明度 | 内容 |
|---|---|---|
| `--lv-bg` | 8% | 地面、背景、远景 |
| `--lv-actor` | 22% | 敌人本体 |
| `--lv-lit` | 42% | 敌人受光面、拾取物 |
| `--lv-ui` | 64% | 可交互控件 |
| `--lv-text` | 88% | 文字 |

**推论**：任何时候你看到一个元素，它的明度必须落在这条阶梯上。落不上去的，要么太亮（降）要么太暗（升），不许留在中间。**这条阶梯也解释了为什么主菜单不能放一整面牌墙** —— 36 张象牙牌会把明度带顶到 90%，抢走全部注意力，而它不可交互。

### 4.7 间距（8 档）

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64` —— 只用这 8 个值。任意 padding 都能化约到其中之一。

## 4.8 美术：inline SVG 算"零资产"

**决策**：敌人、拾取物、特效一律用 **inline SVG** 画，不用位图。

| | 位图（png/jpg） | inline SVG |
|---|---|---|
| 是否进仓库 | 是，每张都要授权 | **否，是标记** |
| 分辨率 | 固定，缩放糊 | 矢量，无损 |
| 光照/受光面 | 得重画 | 一层 `linear-gradient` 叠上去就行 |
| 水墨边缘 | 得手绘或后处理 | `feTurbulence` + `feDisplacementMap` |
| 换配色 | 重画 | 改一个 CSS 变量 |

**剪影优先。** 割草游戏要在 0.1 秒内读出"这是什么、危不危险"，靠的是轮廓和明度，不是细节。
每型一条主剪影路径 + 内部结构线 + 面纹汉字。受光面用 `linear-gradient(148deg)` 叠在同一条路径上（方向必须跟 §4.5 的主光一致）。

样张见 `design/foe-art.js`（8 型 + Boss）与样张页「敌人美术」。

### ⚠️ 性能分级：不能给全部敌人上滤镜

`feTurbulence` 是逐像素噪声，**200 个带滤镜的 SVG 会直接掉帧**。必须分档：

| 档 | 数量 | 画法 |
|---|---|---|
| 杂兵（兵/裂） | 数十~上百 | 简化剪影，**不加滤镜**，或只用 `feDropShadow` |
| 精英（铁/盾/巫/影/弓/爆） | 十余 | 完整剪影 + 滤镜，`numOctaves` 降到 1 |
| Boss | 1 | 全部滤镜 + 旋转环 + 核心 |

并且要做**对象池**（复用 DOM 节点），不能每次生成新的 SVG 节点。
现状引擎里「200 敌 DOM 墙性能」本来就是已知待办项，换 SVG 后更需要先解决池化。

## 5. 战斗页 HUD

### 布局原则

参考弹幕/割草类游戏的通行结论：**遮挡战场不是审美问题，是公平性问题**。玩家必须能一眼扫完整片战场，所以：

```
┌──────────────────────────────────────────────────────┐
│ A 血量/等级        B Boss 三段条         C 波次/计时    │  ← 顶边（高 76px）
│                                                      │
│  B 状态徽章                                         │
│  ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐         │
│  │                                          │         │
│  │            净 空 区  永 久 净 空          │         │  ← 中央 60%，零 UI
│  │                                          │         │
│  └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘         │
│                                                      │
│        B 手牌（14 格，不压角色）                       │  ← 高 96px
│ C 货币              A 怒气/Overdrive      B 武器槽   │  ← 底边（高 68px）
└──────────────────────────────────────────────────────┘
```

**只允许 6 个锚点**：四角 + 顶边中段。任何新增 UI 先问"它属于哪一档、放哪个锚点"，放不下就说明它不该常驻。

### 信息紧急度分档（这是 HUD 设计的真正规则）

| 档 | 内容 | 视觉处理 | 举例 |
|---|---|---|---|
| **A · 决策相关** | 战斗中必须余光可见、要立刻做判断 | 高对比 + 有语义色 + 有动态 | 血量、怒气、Boss 血条、玩家受击反馈 |
| **B · 节奏相关** | 影响操作节奏但不需要精确读数 | 中对比 + 形状/图标辅助，不靠颜色 | 经验条、手牌与听牌角标、武器 CD 扇形、状态徽章 |
| **C · 余光可读** | 结算时才需要精确数字 | 低对比、小字号、等宽 | 金币/代币/核心、用时、击杀数、关卡名 |

**推论**：C 档不许用强调色。如果一个数字永远不需要你在战斗中读准，它就不该是金色。

### 三个进度条（同形状语言：玉佩收分）

`clip-path` 做上下收分的梯形，三条共用，只换语义色：

| 条 | 色 | 高 | 档 | 附加反馈 |
|---|---|---|---|---|
| 血量 | 朱砂 | 18px | A | 受击 `brightness(2.4)` 闪一下 180ms |
| 怒气 | 鎏金 | 14px | A | 满槽时外发光 + 扫光动画 + 「空格·发动」角标 |
| 经验 | 竹青 | 6px | B | 无（太细，不加反馈） |

**数值写在条内右侧**，带 `text-shadow: 0 1px 2px rgba(0,0,0,.9)` —— 不写在条外，因为条外会占掉净空区。

### Boss 三段条

顶边正中，横向 720px，分 3 段对应 3 阶段：

- 已破阶段 = 暗灰填充；当前阶段 = 朱砂填充 + 1px 朱砂内框；未至阶段 = 空槽
- 段下方一排「一·已破 / 二·现在 / 三·未至」，**段断本身就是阶段转换预警**
- 名称用衬线朱砂在左上，阶段描述（弹幕/瞬移/狂暴）在右上

### 手牌

- 14 格横排在战场下方 118px 处，**不压角色**
- 牌宽 52px、高 68px、间距 5px
- 状态：`is-out`（不可打，亮度 .5）/ `is-sel`（上浮 10px + 鎏金 2px 环）/ `is-ten`（右上鎏金三角角标 = 听牌）
- 顶部一行 `手牌 13/14 · 已听牌`，12px mono
- 满 14 张时横向滚动，不换行、不缩放

### 飘字（只有三种语气）

| 类 | 色 | 字号 | 含义 |
|---|---|---|---|
| `.fct--crit` | 鎏金 | 40px | 暴击 / 价值（唯一用金的原因） |
| `.fct--dmg` | 朱砂 | 26px | 受到的伤害 |
| `.fct--heal` | 竹青 | 26px | 治疗 / 增益 |

全部 1.1s 向上飘 54px + 淡出，`text-shadow` 强描边保证在乱战里可读。**不加弹跳、不加旋转**。

### 战斗页质感

- 战场底：`radial-gradient` 深墨 + 80px 网格（`rgba(228,236,239,.028)`，与引擎 `GRID_SIZE=80` 对齐，只给眼睛一个尺度）+ 3 个错位大径向渐变当"水墨晕"，替代图片素材
- 全局扫描线：1px / 3px 循环，opacity `.022`，`mix-blend-mode: overlay`
- 暗角：`inset 0 0 240px 60px rgba(0,0,0,.55)`
- 质感层放最后，**不承担任何结构职责**；`body.no-texture` 可整体关掉（低端机/性能）

## 6. 三选一面板

全场出现频率最高的弹层，优先级最高。

- **遮罩**：`rgba(6,9,11,.60)` + `blur(4px)` —— 背景战场要"看得见但不重要"，这是让玩家知道自己暂停在哪的锚
- **卡片** 316 × 428，三张横排 gap 24
- **品质靠描边语言区分，不新增颜色**：
  - 传说 = 鎏金边框 + 鎏金角标 + 鎏金顶栏
  - 史诗 = 竹青
  - 稀有 = 象牙
- **卡片信息四段**：品质+等级点阵 / 名称+英文 tag / 描述 / **数值预览 `0 → 新值`**
  - 数值预览是这套设计里最值钱的一条：玩家选卡要的是"变多少"，不是"是什么"
- **hover**：上浮 6px + 边框亮到品质色 + 外投影
- **底部操作提示**一行说清：点击 / 数字键 / 重掷 / 跳过

## 7. 大本营

### 信息架构（解决"什么都挤在一屏"）

调研里最有用的一条结论：**把"长期养成"和"本次出征"分成两栏，玩家才知道该先做哪件事**。三区 + 底栏：

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏 72px  印章 + 标题 | 资源条：代币 核心 金币 最深 登录    │
├──────────┬──────────────────────────────┬──────────────────┤
│ 左轨     │ 中栏：当前面板                │ 右栏：出征准备    │
│ 152px    │ 1fr（可滚动）                │ 400px            │
│ 9 项     │ 天赋/锻造/图鉴…               │ 选将 → 选关 → 词条│
│ 竖排     │ 一行一件事                    │                  │
├──────────┴──────────────────────────────┴──────────────────┤
│ 底栏 100px  自动存档提示        洗练词条 · 继续上局 · 出征  │
└────────────────────────────────────────────────────────────┘
```

- **左轨图标用单个汉字**（酒/赋/锻/征/变/鉴/成/统/史）放在 24px 描边方块里，衬线 15px。比抽象几何记号好认得多，且零素材
- **中栏行结构固定 5 列**：`44px 图标 | 1fr 名称+描述 | 132px 等级点阵 | 108px 价格 | 92px 按钮`
  - 等级用点阵不用进度条：8 个点一眼看完，不需要读数字
  - 价格右对齐等宽；买不起显示「不足」而不是变灰（保留信息）
  - 行之间用 1px 分隔，不用卡片盒子套卡片盒子
- **右栏三段递进**：选将（4 张牌面）→ 选关（3 行）→ 词条（徽章组）
- **底栏只有一个实心金按钮「出征」**；「洗练词条」是 ghost，「继续上局」降级为无边框文字按钮（它不是主行动，别跟出征抢）

## 8. 主菜单（index.html）

玩家打开网址看到的第一屏。它最容易滑向"居中大标题 + 发光金按钮 + 背景渐变"的模板，所以这一屏刻意用**非对称分割 + 单主体打光**对抗。

```
┌──────────────────────┬─┬────────────────────────────┐
│  印章「麻」            │ │        ▤ 九筒（虚）          │
│                      │ │                  ▤ 發（更虚）│
│  麻 将 江 湖          │▓ │                            │
│  MAHJONG SAGA        │ │        ┌────────┐            │
│  一波又一波，直到胡牌。│ │        │   中   │ ← 唯一主体   │
│                      │ │        └────────┘            │
│  [开 始 游 戏]  设置 关于│ │      ▤ 東（最虚）             │
│                      │ │      ▁▁▁▁▁▁▁ 地平线 ▁▁▁▁     │
│  第3赛季 最深 本地存档  │ │   144 张 · 34 种牌面        │
└──────────────────────┴─┴────────────────────────────┘
```

**为什么这样**

1. **只有一张牌被打亮。** 268×350px 的「中」牌立起来，`rotateY(-17deg) rotateX(4deg)` 造出侧面透视；左上受光、右下压暗；牌底有短而实的接触阴影 + 一道往左下拉的长投影；地面有一块比影子亮的椭圆光池把它"焊"在地上。
   > 纯黑背景上黑影是看不见的 —— 必须先有比影子亮的地面，接触关系才成立。
2. **后面三张牌做景深**，逐级 `blur + brightness` 递减（.62 / .46 / .32）。压得太狠会糊成灰斑，读不出是牌 —— 这是实测出来的边界。
3. **象牙在这屏是"高光"，不是"色块"。** v1.0 这里放过一整面 9×4 的牌墙（36 张），结果违反 §4.6 明度带：一片 90% 明度的米色块抢走全场注意力，而它不可交互。**这是本项目最重要的一条反面教材，已写进规范。**
4. **文字只有 4 组**：主标题 / 英文副题 / 一句定位 / 行动区。不加 eyebrow、不加特性列表、不加信任条。
5. **定位句写玩法不写玄**："一波又一波，直到胡牌。"
6. **一个主 CTA**。`开始游戏` 实心金；`设置` / `关于` 降级为无边框文字按钮。**这里不提供"继续上局"** —— 那是 s1 存档页的职责，两屏都放同一个行动就是意图重复。
7. **远景**：三层错位水墨山 + 雾带 + 地平线暖辉。山脚必须落在地平线（约 `bottom: 20%`）而不是屏幕最底 —— 压在最底会被前景压暗层吃掉，等于白画。
8. 中间那条 1px 鎏金竖线跟着主光走，**上亮下暗**。

**注意**：现在的 `index.html` 是绿金渐变 + 发光标题 + 缩放按钮 + 8px 圆角，与本规范全面冲突（只有 52 行、零依赖，替换成本极低）。

## 9. 存档页（480 × 720 竖版）

唯一竖版页（其余都是 1920 × 1080）。单列，从上到下只做四件事：

1. 印章 + 「麻将江湖」+ `MAHJONG SAGA`
2. 存档条目（牌面 + 赛季名 + 进度 + 时间），当前档鎏金描边
3. **一个主 CTA**「继续征途」（实心金）→ 两个次级（开启新征程 / 设置）→ 两个三级（小号，导入 / 导出）
4. 版本与备份提示

竖版空间紧张，所以层级靠**尺寸和填充度**拉开，不靠边框花样。

## 10. 动效

| 令牌 | 时长 | 用在哪 |
|---|---|---|
| `--t-fast` | 120ms | hover、按下、边框变色 |
| `--t-mid` | 180ms | 面板入场、卡片浮起、血条受击闪 |
| `--t-slow` | 320ms | Boss 段条填充、结算演出 |

- 缓动只用 `--ease: cubic-bezier(.2,.7,.3,1)`
- **按下 = 下沉 1px**（`translateY(1px)` + 去掉投影），不做抖动、不做缩放弹跳
- 面板入场：`opacity 0→1` + `translateY(8px)`，不做缩放
- 数字变化**不做滚动动画**（战斗中每秒几十次，纯浪费性能），只闪一次颜色
- `@media (prefers-reduced-motion: reduce)` 全局关动画
- 只动 `transform` 和 `opacity`

## 12. 无障碍与可读性

- 所有正文/数字对底色 ≥ 4.5:1（AA），关键数字 ≥ 7:1
- 状态永远**颜色 + 形状/文字**双编码：血量是红的**且**有数字，冻结是青的**且**有角标，禁用是灰的**且**写着「不足」。红绿色盲玩家不会丢失任何关键信息
- 按钮四态齐全：默认 / 悬停 / 按下 / 禁用；`:focus-visible` 2px 鎏金外框
- 尊重 `prefers-reduced-motion`
- 正文字号下限 12px（仅限全角角标），正文最小 14px
- 界面文字全部中文，无中英混排歧义

## 13. 迁移路径

| 阶段 | 做什么 | 风险 |
|---|---|---|
| **P0 换肤** | 把 `tokens.css` 引入 `common.css` 之后，替换 s1/s2/s3 的颜色与字体令牌。DOM 结构一行不动。 | 极低。视觉立刻统一，但布局还是乱的 |
| **P1 组件重做** | 按钮 / 进度条 / 牌面 / 徽章 / 三选一 卡片按本文规格重写 CSS 类，替换旧类名 | 低。这几类在旧代码里边界清晰 |
| **P2 HUD 重排** | 战斗页 HUD 改为四角 + 顶边锚点，抽出 `HudLayout` 模块统一管理位置 | **中**。要动 `GameEngine.Render.js` / `Loop.js` 里所有写 HUD 位置的代码 |
| **P3 大本营重排** | 9 个 Tab 改成左轨 + 三区布局，`main_hub.js` 的面板切分要重写 | **高**。1831 行的页面控制器，牵一发动全身 |
| **P4 清理** | 删除旧 CSS 变量和孤儿选择器；同步 `GAME_BIBLE.md` 视觉章节 | 低 |

**不建议**一次性全推。P0 单独上线就能拿到 60% 的观感提升，代价几乎为零。
