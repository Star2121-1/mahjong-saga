## T1 ⚠️ 做了什么 / 没做什么

### 计划前提被实测推翻（已更新 PLAN.md）
原以为 CSS 走 `--mj-*` 令牌层。实测：**4000 行 CSS 里 `--mj-*` 只用了 1 次**；
真实情况是 **685 处硬编码 hex + 651 处 rgba、236 种唯一色值、15 种 border-radius**。
令牌层是摆设 —— 这才是「乱」的根源。

因此改用**可回滚的覆盖层** `css/theme-mokudan.css`（三页最后一个加载，删掉即 100% 回滚），
而不是原地重写 4000 行。

### 已生效
- `css/tokens.css` + `css/theme-mokudan.css` 已接入三页（`?v=20260926A`）
- **战场底**：`#battlefield` 从 `radial-gradient(..., #2a7348, #1a5c38, #134a2e)`
  （明度约 45% 的高饱和绿，占屏 90%）改为墨底 + 左上主光的极淡衰减。
  **单项收益最大的一处** —— 前后截图对比见 `audit/before-fix/s3.png` 与 `audit/after-fix/s3.png`
- 三条进度条改语义色：玩家血=竹青 / 经验=竹青(细) / 怒气=鎏金 / 敌人血=朱砂
  （玩家与敌人永不同色，不会混淆）
- 圆角收敛、弹层表面改墨玻璃、focus 环、等宽数字

### 我犯的错（如实记）
第一版覆盖层里的选择器（`.hp-bar` / `.fct-node.crit` / `.enemy-hp-fill` …）是**我编的**，
没读过真实 CSS。证据：加不加覆盖层，色值数一模一样（21/41/44）—— 规则一条没命中。
这是「幻觉选择器」。已改为真实选择器（`#player-hp-fill` / `#exp-bar-fill` / `#rage-bar-fill` 等）。
**教训：写覆盖层前必须先 grep 出真实类名。**

### 测量工具本身也踩了三个坑（都已修）
1. `compare.js` 拿 `body.children` 比 `body *` —— 量纲不一致，"暴涨"是假警报
2. s3 无存档会**跳回 s1** —— 检查跑在错误的页面上，`gameEngine` 报 undefined 却是页面被重定向
3. s3 新存档 `hasSeenGuide=false` —— 截图一直拍到**新手指引**而不是战斗 HUD，
   测出来的节点数/色值全是引导层的。现已改为直接调 `gameEngine._completeGuide()`

## T2 方案修正（重要，方案本身错了）

原计划：把敌人换成 `design/foe-art.js` 里那套抽象 SVG 水墨剪影。

**实测后发现那是退步。** 敌人现在**本来就是麻将牌** —— `.enemy` 是象牙牌体，
`::before` 显示 `data-suit` 的萬/條/筒/索/白/風/發/中（`Enemy.js:1294` 的 `suitMap`）。
「敌人 = 一张牌」是这个游戏的题眼，换成抽象妖怪反而丢题材。

真问题是**执行**，已改（`css/theme-mokudan.css` §15）：
- 厚度从 8 层 `box-shadow` 堆叠 → 2 层（右侧 + 底部），渲染更省、边缘更干净
- 去掉 `::after` 的 `data-type` 文字标签（7px / opacity .6）→ 18 个敌人就是 18 条小字，纯噪声。
  改为**边框色 + 形状双编码**区分敌型，色盲玩家靠形状也能分辨
- 花色字提到 22px 衬线，去掉白描边
- 血条压低对比度

`design/foe-art.js` 与 `UI_SPEC.md` §4.8 的 SVG 方案**保留但降级**为备选：
若将来要做「牌灵」题材（敌人不再是牌而是妖怪），那套剪影可直接用。

## 实测发现的问题（T1/T3 已解决的）

拿到真实战斗画面后（`audit/after-fix/s3.png`），颜色已经不是主因，**布局才是**：

1. **顶栏 HUD 挤成一条细带** + 两条**横贯 1920px 全屏**的进度条（Lv 和怒气）。
   为 3 位数用的条占满全屏，信息密度与视觉权重完全不成比例
2. **手牌是 14 个空槽装在一个巨大的金框盒子里**，空槽时占屏宽 80%
3. **`120/120` 文字压在玩家牌面上**，两者重叠
4. 底部「飞牌切」条与计时条同样全屏宽
5. 敌人是小尺寸深色胶囊 + 顶部红条，**没有剪影**（这正是 T2 要解决的）

**结论：颜色覆盖层已经到头了。** 上面 1~4 都是布局问题，只能靠 T3 组件重做
（改 `css/gameplay/gameplay-ui.css` / `gameplay-player.css` 的布局规则）。
继续加覆盖层不会有明显收益。
